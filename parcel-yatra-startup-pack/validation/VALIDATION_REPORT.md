## 3. Check C2 — duplicate YAML key detection (control test)

Validation of our spec alone does not prove the validator would have *caught* duplicate keys. A control
file was created to prove the check is real.

**Control file** (`C:\Users\kurmi\AppData\Local\Temp\opencode\dupkey-test.yaml`)

```yaml
openapi: 3.1.0
info:
  title: Dup test
  version: 1.0.0
  version: 2.0.0
paths: {}
```

**Command**

```powershell
npx -y @redocly/cli@latest lint C:\Users\kurmi\AppData\Local\Temp\opencode\dupkey-test.yaml
```

**Result: control correctly REJECTED** — exit code `1`.

```
Failed to parse API description at ...\dupkey-test.yaml:

  - duplicated mapping key in "...\dupkey-test.yaml" (5:3)
```

**Conclusion:** the validator rejects duplicate YAML mapping keys. Our spec passed the same validator,
therefore `api/openapi.yaml` contains no duplicate keys within any single mapping. This is evidence, not
an assumption.

**Limitation:** this proves no duplicate keys exist. It does not prove semantic correctness — that the
42 operations do what the product needs. Semantic review is a human task (see §8).

### C8 detail — the single flagged line

```
ux/CONTENT_AND_MICROCOPY.md:175
| "Escrow" / "we hold your money" | GATE-3 provider confirmation (and even then, prefer "held by our payment p
```

**Verdict: false positive.** This line is a row in the table of phrases that are *blocked until a gate
clears*. The phrase appears precisely because the document forbids it. No change was made.

The scanner searched for: `is compliant with`, `100% secure`, `guaranteed delivery`, `we hold your
money`, `production-ready`, `India's #1`. No other instance of any of these appears as a positive claim
anywhere in the pack.

**Limitation:** a regex scan cannot catch a subtly worded overclaim ("trusted by thousands"). That class
of error is only catchable by reading. `validation/CLAIMS_AND_LIMITATIONS.md` exists for exactly this
reason, and `testing/UAT_CHECKLIST.md` §18 makes the human read a release gate.

## 12. What this report does not establish

Passing every check above means:

- the OpenAPI file is syntactically valid and has no duplicate keys,
- the documentation files exist, are internally referenced consistently, and contain no
  machine-detectable overclaim.

It does **not** mean:

- the product works,
- the product is secure,
- the product is legally compliant,
- the product has a market,
- a single line of the legal drafts has been reviewed by a lawyer,
- any number about demand, price or performance has been measured.

Those are the twelve unrun checks in §8, and they are the ones that decide whether this becomes a
business.
