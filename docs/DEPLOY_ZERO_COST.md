## New Environment Variables

| Variable | What it does |
|---|---|
| `STORAGE_PROVIDER` | `local` (default) or `cloudinary` |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary cloud name |
| `CLOUDINARY_API_KEY` | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret |
| `MIGRATE_ON_BOOT` | `true` → apply pending migrations at boot (safe for Railway) |
| `DATABASE_SSL` | `require` for Railway PostgreSQL |
| `TRUST_PROXY` | `true` when behind Railway's reverse proxy |

## What the Build Does

```
Dockerfile:
  Stage 1 (deps)     npm ci all workspaces
  Stage 2 (builder)  esbuild bundles API → dist/index.js
                     Vite builds Web → apps/web/dist/
  Stage 3 (api)      Minimal Alpine, runs dist/index.js
                     CMD: node dist/migrate.js && node dist/index.js
```

The web `dist/` is built in the Docker image but **not served by the API** — deploy `apps/web` separately to Vercel (it's a pure static site).

## Accessing Logs

```bash
# Railway CLI

# Or in the Railway dashboard → your service → Deployments → View Logs
```

## OTP in logs (SMS_PROVIDER=log)

When `SMS_PROVIDER=log`, OTPs are written to the structured log as:

```json
{"level":"warn","otp":"123456","purpose":"login","reference":"...","delivery":"operator-log","msg":"OTP issued — relay this code out of band"}
```

**Access to the log is equivalent to access to the account.** Restrict Railway log access accordingly.
